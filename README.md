# Помощник официанта — Telegram MVP

Первая версия для ресторана в Нижнем Новгороде, Большая Покровская, 49. ВКонтакте в эту сборку не входит.

## Что уже есть

- Telegram-бот с заявками на доступ и командами администратора.
- Telegram Mini App, адаптивное под телефон и тёмную тему.
- Каталог из предоставленного архива HTML: основное меню, бизнес-ланч, детское меню, соусы/специи, спецпредложение и безалкогольные позиции бара.
- Поиск по названию, ингредиентам, категории и описанию.
- Состав, описание, дополнительная информация, особенности подачи и фотографии.
- Начало и завершение смены.
- Стоп-лист с причиной, временем и сотрудником; история действий сохраняется.
- Внутренние черновики заказов по столам: добавление позиций, количество, заметки, комментарий к заказу, сохранение и удаление.
- SQLite в постоянной папке `/app/data` на BotHost (если папка доступна), иначе локальная `data/`.
- Telegram Mini App `initData` валидируется на сервере. Пользователь должен быть предварительно одобрен.

## Исправление регистрации

Telegram не требует от пользователя фамилию и username. Регистрация нормализует отсутствующие поля в пустые строки, поэтому ошибка SQLite `NOT NULL constraint failed: employees.last_name` исправлена. Существующую базу удалять не нужно.

## Важные границы первой версии

1. Черновики заказов не отправляются в кассу или на кухню.
2. В учебных HTML-экспортах нет полного прайс-листа. У позиций цена пустая, поэтому сумма заказа не выдумывается и пока не рассчитывается.
3. В эту версию импортированы только безалкогольные позиции бара.
4. Кухне не требуется устанавливать Telegram или использовать приложение. Сотрудник ресторана меняет статус по сообщению от кухни.
5. При первом запуске каталог загружается в SQLite. Последующие старты обновляют текстовые поля меню, но сохраняют текущие статусы стоп-листа.

## Настройка на BotHost

1. Создай Telegram-бота у `@BotFather`, скопируй токен.
2. Загрузи эту папку в частный GitHub-репозиторий. ZIP с проектом не содержит токена или других секретов.
3. В BotHost создай Telegram-проект, подключи репозиторий и укажи точку входа `main.py`. Приложение слушает `PORT` из окружения, по умолчанию `3000`, на адресе `0.0.0.0`. В настройках веб-приложения включи публикацию домена с HTTPS.
4. В переменных окружения задай:
   - `BOT_TOKEN` — токен от BotFather;
   - `ADMIN_TELEGRAM_IDS` — твой Telegram ID; можно несколько ID через запятую;
   - `WEBAPP_URL` — HTTPS-адрес приложения на BotHost, например `https://имя-приложения.bothost.ru`;
   - по желанию `DATABASE_PATH=/app/data/restaurant.db`.
5. Перезапусти приложение и открой его HTTPS-адрес в обычном браузере. Должен открыться стартовый экран; полноценная авторизация Mini App работает только при запуске внутри Telegram.
6. Напиши своему боту `/start`. Чтобы узнать свой ID до настройки, открой бота и отправь `/id`; добавь этот ID в `ADMIN_TELEGRAM_IDS` в BotHost и перезапусти приложение.
7. В `@BotFather` настрой Menu Button на HTTPS-адрес Mini App (если нужно, бот также покажет inline-кнопку после `/start`).
8. Напиши `/start` ещё раз. Администратор автоматически получит права. Остальные сотрудники сами пишут `/start`, после чего у администратора появляется заявка в `/pending`.

## Управление доступом

- `/id` — Telegram ID текущего пользователя.
- `/pending` — заявки, доступно ID из `ADMIN_TELEGRAM_IDS`.
- `/approve 123456789 waiter` — одобрить официанта.
- `/approve 123456789 manager` — одобрить менеджера.
- `/approve 123456789 admin` — одобрить администратора.
- `/employees` — список сотрудников.

Сначала сотрудник нажимает `/start` у бота, затем администратор одобряет его. После одобрения пользователь должен заново открыть Mini App.

## Локальный запуск для проверки

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
$env:BOT_TOKEN="токен_от_BotFather"
$env:ADMIN_TELEGRAM_IDS="123456789"
python main.py
```

В Linux/macOS используй `source .venv/bin/activate`, затем `export BOT_TOKEN="..."` и `export ADMIN_TELEGRAM_IDS="123456789"`. Для полноценного Mini App в Telegram нужен развёрнутый HTTPS-адрес; `localhost` здесь не заменяет продакшен-домен.

Без `BOT_TOKEN` запускается только веб-сервер; Telegram-бот и защищённая авторизация не работают. Не включай режим доверия к клиентскому Telegram ID — проверка выполняется по подписи `initData`.

## Структура

```text

public/style.css       Адаптивный дизайн
public/app.js          Интерфейс и запросы к API
public/images/         Оптимизированные фотографии блюд
requirements.txt       Зависимости
```

## Перед рабочим использованием

- Проверь данные карточек и корректность состава/ограничений с оригинальным актуальным меню.
- Добавь отдельный актуальный прайс-лист, если нужно показывать цену и считать сумму.
- Проверь постоянное хранилище и регулярные резервные копии SQLite в настройках хостинга.
- Протестируй с несколькими аккаунтами: заявку, одобрение, активную смену, параллельное изменение стоп-листа, черновики и завершение смены.
- Не вводи в приложение реальные данные гостей; эта версия не предназначена для хранения персональных данных гостей или платёжной информации.
